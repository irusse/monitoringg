# PROMPT 05 — Isolated RS-485 HAL

MESH 485 Extender. Phases 01–04 are done. Do **only** this run.

## Product (do not expand)

Heltec V4 already has MeshCore BLE+USB and Access OLED/Wiegand. This run adds a **UART RS-485 port with DE/RE**. No Bolid parser, no Flutter, no ACL.

## Read first

- `AGENTS.md`
- `docs/pinout.md`
- `hardware/rs485-adapter.md`
- `docs/architecture.md`

## Rules

- GPIO **19/20 = USB**. Never RS-485.
- Do not steal OLED 17/18/21, LoRa SPI, or Access Wiegand/relay/sensor pins.
- Prefer isolated transceiver. Bench may use a dongle; document it.
- Do not fork `vendor/MeshCore`.
- Keep Access OLED as the home screen. Optional line `RS485 idle` is OK; no MeshCore chat.

## Deliverables

1. Freeze RS-485 TX/RX/DE in `docs/pinout.md`, `pins.h` (or `include/hal/rs485_pins.h`), `hardware/wiring.md`, `hardware/rs485-adapter.md`. Proposed: TX 39, RX 38, DE 26 (GNSS UART unused). If the module uses those pins, write a silkscreen exception and pick alternatives.

2. `Rs485Hal`: begin(baud, parity, stop), `setDirection(tx)`, write frame, read with timeout, loop() non-blocking. Default 9600 8N1. Config struct for 19200–115200.

3. Bench: USB-RS485 ↔ Heltec. Serial/OLED proof of echo. MeshCore `loop()` still runs.

4. Note in `docs/implementation.md` Phase 05. Update `firmware/heltec_v4/README.md`.

## Done when

Pin files match. Loopback works or the blockage is written (missing isolator). Access OLED and USER menu still work.

Then stop. Next: `prompts/06-mesh485-protocol.md`.
