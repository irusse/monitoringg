PROMPT 27 — RDM6300 на ноде мониторинга в существующий ACL

Ты продолжаешь **MESH 485 Extender**. Каскад 01–23 закрыт. Прогоны **25** и **26** сделаны. Делай **только** этот файл. Не listen-only С2000-М (это 24), не совместный стенд двух плат (это 28). Доставку ПЦН не переписывать.

Цель: нода мониторинга читает карту 125 кГц с RDM6300 и решает проход тем же ACL, что уже обслуживает Wiegand (`TS-001`). Меш для решения не нужен. Живой модуль для зелёного теста не обязателен: хватает байтовой фикстуры.

## Уже есть, не ломать

- GPIO 47 → EventStore `PCN-001`. Хоп на `EXT-002`: 59 байт, `source` `LORA`, тот же uuid, ack ставит `mesh_ok`. Код: `mesh485/pcn_hop.h`, `pollPcnHop` / `acceptPcnFrame`, `AccessMesh` в `meshcore_adapter`. Кадр ПЦН не открывает GPIO 40.
- DISCOVER — шесть id: `RAW-001`, `TS-001`, `PP-001`, `S10-001`, `S20-001`, `PCN-001`. Седьмой id под считыватель не заводить. Карта остаётся событием `TS-001`.
- Пустой ACL = DENY. `ACCESS_ADD_CARD` / `ACCESS_REMOVE_CARD` / `ACCESS_OPEN` / `ACCESS_LOCK` те же команды. `CONFIG_SET AUTO` отказ.
- GPIO **19/20 = USB**. Фото не в JSON. Companion mux `{` на месте. `vendor/MeshCore` не форкать. Не чат, не `sendTxt`, не QR.
- Образ монитора собирается с `-D MESH485_NODE_ID=\"EXT-002\"`. Этот прогон id не меняет.

## Железо

Только нода мониторинга. UART1 на ней не шина «Орион» и не нода у панели.

- RDM6300 TX → GPIO **38** (UART1 RX), 9600 8N1. 5 В через делитель (2,2 кОм к пину, 3,3 кОм пин на GND). Распиновка: `docs/pinout.md`, провода: `hardware/wiring.md`.
- RX модуля не подключать. Питание модуля — 5 В, не GPIO. GND общий.
- GPIO **26** держать RX (LOW), если трансивер RS-485 на плате ещё стоит. GPIO **39** под считыватель не занимать.
- В этом режиме Wiegand D0/D1 (GPIO 15/16) не опрашивать. Оба входа сразу не вооружать.
- Нода у панели UART1 считывателю не отдаёт.

## Кадр

`0x02`, 10 hex-символов (5 байт карты), два символа контрольной суммы (XOR этих пяти байт), `0x03`.

Чужая длина, мусор или неверная сумма — счётчик ошибок UART, не событие карты и не UID. Один и тот же UID примерно в пределах 2 с — одна запись, не поток кадров.

UID в существующий ACL (`AccessController::checkUid`). Пустой список — DENY, красная лампа, GPIO 40 молчит, событие отказа есть. Карта из списка — GRANT, импульс OPEN как у Wiegand, зелёная лампа, OLED «ДОСТУП ОК». Событие `source` `RFID`, `device_id` `TS-001`.

Потеря радио не выключает разбор и не обнуляет список. Отдельный протокол команд считывателя не вводить. Флаг «игнорировать новые чтения» допустим только как локальная настройка; пропадание меша само его не включает. Тревога ПЦН турникет по-прежнему не открывает.

## Что сделать

1. Разбор кадра без платы: фикстура байтов → UID. Битая сумма → не карта. Повтор внутри окна → одна запись.
2. Тот же путь, что `noteCard` / `checkUid` в `main.cpp` для Wiegand. Новый экран Flutter и новый клиент не делать. Fixture может содержать одну карту `RFID`, если плитка от этого не врёт.
3. Native: пустой ACL → DENY и GPIO 40 / `AccessGate` остаётся `LOCKED`. Карта из списка → OPEN. Хоп ПЦН из прогона 26 по-прежнему одно `ALARM` и одно `NORMAL` без дубля и без OPEN.
4. Коротко `docs/implementation.md` Phase 27, `docs/report-27-ru.md`, строка в `agent/CASCADE.md`. `AGENTS.md`: next = `agent/prompts/28-pcn-acs-bench.md`.
