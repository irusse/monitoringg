PROMPT 25 — сухой контакт ПЦН «Тревога» → EventStore на ноде у панели

Ты продолжаешь **MESH 485 Extender**. Каскад 01–23 закрыт. Прогон **24** (listen-only RS-485 С2000-М) — отдельная задача, в этом прогоне её не делать. Делай **только** этот файл. Не передачу на вторую ноду (это 26), не RDM6300 (это 27), не стенд двух плат (это 28).

Цель: нода у панели читает выход ПЦН как сухой контакт и пишет честное событие в EventStore. Оператор видит его в существующем Flutter **События** по USB/BLE этой ноды. Образ остаётся MeshCore Companion.

## Продукт

```
Реле ПЦН С2000-М ── оптопара ── GPIO 47
                                    │
                              EventStore / EVENT_LIST
                                    │
                         Flutter События (USB/BLE этой ноды)
```

Панель жива, если Heltec выключен. Замыкание контакта — это «Тревога», потому что его замкнула панель, а не потому что разобран кадр «Орион».

## Заморожено

- GPIO **19/20 = USB**. RS-485 **39 / 38 / 26** в этом прогоне не занимать под считыватель и не поднимать DE.
- ПЦН = GPIO **47**, `INPUT_PULLUP`, активный уровень LOW. Распиновка: `docs/pinout.md`, провода: `hardware/wiring.md`.
- Фото никогда на узел / OLED / LoRa / JSON.
- OPEN = `ACCESS_OPEN`. Контакт ПЦН импульс на GPIO 40 не даёт.
- Пустой ACL = DENY. AuthZ 20–22 не ломать. `CONFIG_SET AUTO` отказ.
- Не форкать `vendor/MeshCore`. Не чат, не `sendTxt`, не contacts, не QR.
- Companion mux не снимать: строка с `{` — MESH 485, остальное — Companion binary.
- `MeshCoreService::send` сейчас заглушка (возвращает «радио живо» и байты не передаёт). В этом прогоне её не «чинить» под видом доставки тревоги. Доставка на вторую ноду — прогон 26.

## Что сделать

1. Вход GPIO 47. Дребезг около 50 мс. Фронт в LOW → одно событие. Фронт в HIGH → одно событие. Удержание уровня новых событий не порождает. Неподключённый вход (HIGH) — тишина, не тревога.
2. Запись в EventStore:
   - `device_id` `PCN-001`
   - `point_id` `ALARM`
   - `type` `PCN`
   - `state` `ALARM` или `NORMAL`
   - `source` `GPIO`
   - `severity` `ALARM` только вместе со `state` `ALARM`; для `NORMAL` severity не пожарная выдумка — `INFO`
   - `device_ok` = 1 (уровень прочитан)
   - `mesh_ok` = 0, пока нет доставки на другую ноду
   - новый uuid и sequence на каждое изменение
3. DISCOVER: добавить `PCN-001`, возможности только чтение/монитор, без CONTROL. В документах и тестах честно написать новое число id. Старые пять id на месте.
4. OLED ноды у панели: строка `ТРЕВОГА` или `НОРМА` по последнему состоянию входа. Экран чата не добавлять.
5. Flutter: существующий список «События» показывает `state` (поле в модели уже есть, плитка его пока не рисует). Новый экран и новый клиент не делать. Fixture может содержать одну запись `PCN` / `ALARM`.
6. Native-тест без платы: имитация фронта → одна запись `ALARM`; удержание → без второй; отпуск → одна `NORMAL`; старт с разомкнутым входом → в списке нет `PCN`. Кадр «Орион» с верным CRC по-прежнему не становится `ALARM` сам по себе.
