# С2000-М и Heltec V4 — подключение и куда уходят сигналы

Продукт: **MESH 485 Extender**. Образ `heltec_v4_access`. Дата: **10 сентября 2026**.

**С2000-М (С2000М)** — прибор приёмно-контрольный «Орион», обычно **мастер** линии RS-485 «Орион». Heltec — **шлюз интеграции**, не второй пульт и не замена панели. Потеря LoRa / USB / приложения **не** должна останавливать С2000-М.

**Не делать:** слать события пожарки **личным сообщением MeshCore** (чат Companion / Open). Это запрещено архитектурой: консоль оператора — MESH 485 JSON, не мессенджер; таймаут шины ~50 мс DE vs RTT меша; mux USB/BLE уже делит `{` и Companion binary. Фиксация сигналов — **EventStore** → `EVENT_LIST` / `m485.event` / экран «События» во Flutter. Между узлами — тот же MESH 485 (компактный кадр события), не DM чата.

Канон пинов: [`pinout.md`](pinout.md). Изолятор: [`../hardware/rs485-adapter.md`](../hardware/rs485-adapter.md). Path A vs B: [`reference/orion-path-decision.md`](reference/orion-path-decision.md).

## Два порта на С2000-М — это не одно и то же

| Порт на С2000-М | Зачем у Болида | К Heltec V4 |
|---|---|---|
| **RS-485 «Орион»** (клеммы A / B линии приборов) | Шина к Сигнал-10/20, считывателям, реле | **Единственный штатный путь.** Изолятор → GPIO **39 / 38 / 26** |
| **RS-232** (часто DB-9 к ПК, «Орион Про») | Компьютер, другой протокол/уровень | **Не на пины Heltec.** ±12 В убьёт ESP32. GPIO **19/20 = USB PHY**, не UART. Второго UART в образе нет |

RS-232 «напрямую в GPIO» — нет. Если когда-нибудь понадобится именно COM ПК: MAX3232 + **отдельный** UART на расширителе, не 19/20, не LoRa SPI, не OLED 17/18/21. Это dual UART — отдельное решение, не этот документ.

## Рекомендуемая схема (Path A) — не вешать Heltec вторым мастером

С2000-М остаётся мастером Orion. Heltec говорит **Modbus** с официальным преобразователем:

```
Сигнал-10 / 20 / …  ←RS-485 Орион→  С2000-М (мастер)
                                      │
                                 С2000-ПП (Orion ↔ Modbus, официально)
                                      │ изолированный RS-485 9600 8N1
                                 Heltec UART1
                                 TX 39  RX 38  DE 26
```

В прошивке: `CONFIG_SET protocol` = `BOLID_C2000PP` (фаза 23: переживает ребут, `/m485_cfg.bin`). DISCOVER: `PP-001`. Пустая шина → `online: false` / `TIMEOUT`, не фейковый пожар.

Пины isolator (логика 3.3 В):

| Heltec | Сигнал | Isolator |
|---|---|---|
| GPIO **39** | UART1 TX | DI |
| GPIO **38** | UART1 RX | RO |
| GPIO **26** | DE/RE | DE (HIGH = TX). Idle = **RX** |
| GND | логика | GND isolator (не «земля мотора» турникета) |
| — | поле | A / B к стороне ПП (120 Ω только на концах линии) |

Питание 12/24 В шины **не** с 5 В Heltec. Антенна LoRa надета до TX в эфир.

## Выход ПЦН «Тревога» — сухой контакт, не шина

Сигнал «Тревога» для этой задачи — реле, которое С2000-М (или блок реле, которым она управляет) уже замыкает на пульт наблюдения. На ноду у панели он приходит через оптопару на GPIO **47** (`INPUT_PULLUP`, замыкание на GND = тревога). Разомкнутый вход — норма.

Это не клеммы A/B и не RS-232. Слушание шины «Орион» остаётся отдельным прогоном 24 и само не стартует. Распиновка двух нод и RDM6300: [`pinout.md`](pinout.md). Когда что проверять: [`test-pcn-acs.md`](test-pcn-acs.md). В образе контакт пишется в EventStore (`PCN-001`) и уходит на вторую ноду сырым кадром, не чатом. RDM6300 на ноде мониторинга читается в ACL `TS-001` (`-D MESH485_RDM6300=1`). Совместный прогон 28 закрыт фикстурой: [`report-28-ru.md`](report-28-ru.md). На образе с RDM6300 UART1 занят считывателем; tap шины — на образе без этого флага.

## Прямое подключение к линии С2000-М (Path B, listen-only)

Если С2000-ПП нет: Heltec может **слушать** ту же RS-485 «Орион», что и панель. С2000-М — единственный мастер. Heltec **не TX** (GPIO 26 держать RX). Иначе коллизии, ретраи, «пропавшие» ведомые.

```
С2000-М A/B ──┬── приборы Орион
              └── isolator A/B (ответвление, без второй терминации посередине)
                    Heltec 39/38/26, DE = RX
```

Правила:

1. Только **изолированный** трансивер (не голый MAX485 на живой пожарке).
2. Смещение/терминация — как у линии; не ставить второй 120 Ω на отводе.
3. Не включать `RAW_BRIDGE` как «прозрачный модем» Orion: меш не 50 мс turnaround ([`orion-timings.md`](reference/orion-timings.md)).
4. Не слать с Heltec кадры «чтобы проверить» и не fire-disable / disarm.
5. Пока нет прогона MONITOR С2000-М: в образе есть `READ_ONLY` `BRIDGE_POLL` (сырые кадры) и MONITOR Сигнал-10/20 **после** ручного `CONFIG_SET`. Разбор событий С2000-М в EventStore — [`24-c2000m-monitor.md`](../agent/prompts/24-c2000m-monitor.md), не чат.

Шина Орион (РЭ С2000-ПП): **9600**, 8N1, пакет до ~75 байт. Кадр Path B: [`orion-frames.md`](reference/orion-frames.md) (CRC-8/MAXIM). Верный CRC ≠ «панель приняла команду».

## Куда фиксировать сигналы (не чат MeshCore)

| Куда | Инструмент | Формат |
|---|---|---|
| Оператор на объекте | Flutter **События** | MESH 485 `EVENT_LIST` / USB `m485.event` |
| Другой узел-шлюз | LoRa как **транспорт MESH 485** | То же событие Device/Point/Event, dual ACK |
| Техник радио | MeshCore CLI / Companion | Ключи, repeater — **не** журнал пожарки |
| Панель | С2000-М сам | Живёт без Heltec |

Цепочка, которую можно реализовать в прогоне 24 (listen-only):

```
RX UART1 (DE=RX) → кадр с валидным CRC-8 → EventRecord (type ORION / raw hex, не выдуманный FIRE)
                 → EventStore → EVENT_LIST / EVENT_SUBSCRIBE
                 → при подписке на меш: публикация MESH 485 event на другой EXT (не DM чата)
```

Пустой разбор «зоны/раздел из С2000-М» без дампов **не** подменять фейковым ALARM. Честный минимум: факт кадра + адрес + hex + `mesh_ok`/`device_ok`.

## Что проверить на стенде

1. С2000-М работает **до** включения Heltec и после его выключения.
2. OLED Heltec: нет постоянного TX (DE не залип в HIGH).
3. `DEVICE_DISCOVER` по-прежнему пять id, пока не сделан адаптер `C2M-001`.
4. Path A: `PP-001` `online: true` только после CRC-valid Modbus read.
5. Listen-only: на `BRIDGE_OPEN` `READ_ONLY` + `BRIDGE_POLL` видны кадры; DE RX.
6. Не искать события в MeshCore Open / «личное сообщение».

Прошивка: `pio run -e heltec_v4_access -t upload`. Mux: `python scripts/m485_devices.py COMx all`.
