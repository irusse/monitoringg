# Отчёт — фаза 26 доставка ПЦН на вторую ноду (13 октября 2026)

Продукт: **MESH 485 Extender**. Образ `heltec_v4_access`. Фаза **25** сделана. Фаза **26** — то же событие на ноде мониторинга, **сделана**.

Это не чат MeshCore и не правка `vendor/MeshCore`.

---

## Реализовано

| Что | Как |
|---|---|
| Кадр | 59 байт: узел-источник, uuid, `state`, sequence отправителя. Magic `0xA5`. Не текст сообщения. |
| Эфир | `MeshCoreService::send` собирает `PAYLOAD_TYPE_RAW_CUSTOM` и зовёт `sendFlood` у уже связанного `MyMesh`. Подкласс `AccessMesh` забирает только кадры с magic хопа, чтобы они не ушли в push сырых данных Companion. |
| Приём | `EXT-002` пишет EventStore: тот же uuid, `source` `LORA`, `type` `PCN`. Повтор uuid вторую строку не создаёт и всё равно отвечает ack. |
| Подтверждение | Короткий кадр с тем же uuid. Отправитель ставит `mesh_ok` = 1. Нет ответа — тот же uuid снова, пауза 1 с, затем 2 с, 4 с… Новый uuid на повтор не выдаётся. |
| Тишина | Журнал отправителя и уровень GPIO 47 не сбрасываются. |
| OLED | Последнее известное состояние ПЦН: своё или принятое. На мониторе это `ТРЕВОГА` / `НОРМА`. |
| Турникет | Кадр не вызывает `ACCESS_OPEN` и не трогает GPIO 40. На шину С2000-М TX нет. |
| USB | `EVENT_SUBSCRIBE` больше не подтверждает строку `PCN`. Иначе `mesh_ok` стал бы 1 без второй ноды. |
| Id | Образ монитора: тот же env и `-D MESH485_NODE_ID=\"EXT-002\"`. |

Native: два диспетчера, копия байтов, без эфира. Одно `ALARM`, одно `NORMAL`, повтор не удваивает журнал.

Живые платы в этом прогоне не гонялись.
