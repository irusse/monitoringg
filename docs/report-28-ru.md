# Отчёт — фаза 28 совместная проверка ПЦН и СКУД (13 октября 2026)

Продукт: **MESH 485 Extender**. Прогоны **25–27** сделаны. Фаза **28** — оба сценария подряд, **сделана фикстурой**. Живых плат, эфира, оптопары, RDM6300 и С2000-М в этом прогоне не было.

Код образа не менялся. Совместный путь уже был в фазах 26 и 27; сюда добавлена одна native-проверка, которая гоняет их на одной паре диспетчеров. Седьмого id нет. Нового экрана Flutter нет.

## Проверено фикстурой

Два `Mesh485Dispatcher` (`EXT-001` и `EXT-002`), копия 59 байт, кадр RDM6300 из прогона 27. Радио и UART не открывались.

| Сценарий | Результат |
|---|---|
| Замыкание контакта | Одно `PCN` / `ALARM` на мониторе, `source` `LORA`. Повтор того же uuid вторую строку не создаёт. |
| Контакт и GPIO 40 | Пока тревога на экране, `AccessGate` остаётся `LOCKED`. |
| Карты нет в списке | `Denied`, турникет `LOCKED`, строка `ТРЕВОГА` остаётся. |
| Карта из ACL | Импульс OPEN, пока `pcnShownState` ещё `ALARM`. Событие прохода — `TS-001`, не новый id. |
| Радио выключено | Недоставленный `NORMAL` держится тем же uuid (пауза 1 с). Список карт на мониторе по-прежнему `Allow`. После «возврата» строка одна, повтор не двоит. |
| Нода у панели выключена и включена при уже замкнутом контакте | Новый кадр не шлётся: первый устойчивый уровень событием не становится (фаза 25). Монитор помнит последнюю доставленную строку и список карт. Это не фейковый пожар. |
| Шина | Хоп и режим считывателя шину не TX. DISCOVER по-прежнему шесть id. |

Flutter (существующие экраны, fixture): в «Событиях» есть `PCN · PCN-001` / `state ALARM` и `CARD · TS-001`. На Access виден проход `TS-001`.

`native_protocol_tests: ok`. `flutter test`: 18 тестов зелёные.
